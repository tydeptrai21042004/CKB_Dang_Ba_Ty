# CKBuilder Passport v4.0 implementation summary

Version 4 extends the v3 production-oriented Passport without changing the deterministic credential trust boundary.

## New real-use features

### Public application
- Optional public credential directory with search, type/status filters, and pagination. It is disabled by default with `PUBLIC_DIRECTORY_ENABLED=0`.
- Public aggregate credential statistics at `/api/stats`.
- Readiness endpoint at `/api/ready` for load balancers and deployment checks.
- Submission status timeline backed by immutable application workflow events.
- Applicant cancellation for `SUBMITTED`/`CHANGES_REQUESTED` submissions.
- Applicant resubmission only after a reviewer explicitly requests changes.
- Gemini BYOK support in addition to OpenAI, OpenRouter, and Groq.

### Issuer/reviewer application
- Operations dashboard with submission, credential, profile, audit, and failed-operation counts.
- Search and status filtering for the review queue.
- Bulk JSON evidence intake for up to 50 submissions per request. Every item still requires individual human review.
- Review state guard: only `SUBMITTED` work can be approved/rejected/requested for changes.
- Operation inspection endpoint for issue/revoke state-machine troubleshooting.
- Operational export endpoint and `npm run backup:export` local backup command.
- Optional signed HTTPS webhooks for issue, revoke, request-changes, rejection, and bulk-intake events.
- Webhook delivery history in the private issuer portal.

## Container deployment hardening
- Production Compose uses separate `.env.public` and `.env.issuer` files.
- Both services support injected process environments without requiring a physical `.env` inside the container.
- A one-shot `issuer-init` service idempotently initializes the issuer trust registry before the public service starts.
- Only the initialization service receives a writable `./secrets` mount; the long-running issuer service mounts signing material read-only.
- `.dockerignore` excludes runtime env files, signing material, databases, logs, and runtime state from the image build context.

## Security properties retained
- The public process never resolves issuer signing key paths.
- AI is optional and requires the user to supply their own key for each browser session.
- AI cannot approve, sign, issue, revoke, modify trust configuration, or override deterministic checks.
- Tracking tokens are hashed in the product database and never included in administrative exports.
- Public directory mode is opt-in because making credential metadata searchable changes the privacy surface.
- Webhook endpoints must use HTTPS, cannot contain credentials, and are rejected when they target localhost/private IP space. DNS results are checked before delivery to reduce SSRF risk.
- Webhooks are HMAC-SHA256 signed with timestamp and delivery identifiers.
- Webhook failure does not roll back a successfully completed credential operation.

## New API surface

Public:

```text
GET  /api/ready
GET  /api/stats
GET  /api/directory?q=&type=&status=&limit=&offset=
POST /api/submissions/:id/resubmit
POST /api/submissions/:id/cancel
```

Private issuer:

```text
GET  /api/admin/stats
GET  /api/admin/submissions?q=&status=&limit=&offset=
POST /api/admin/submissions/bulk
GET  /api/admin/operations
GET  /api/admin/webhooks
GET  /api/admin/export
```

## Optional webhooks

Enable only in the private issuer environment:

```env
WEBHOOK_URL=https://example.org/ckbuilder-hook
WEBHOOK_SECRET=<at-least-24-random-characters>
```

Receiver verification input is:

```text
HMAC_SHA256(secret, "<x-ckbuilder-timestamp>.<raw-request-body>")
```

and is sent as `x-ckbuilder-signature: sha256=<hex>`.

## Backup

```bash
npm run backup:export
# or choose a destination
npm run backup:export -- /secure/path/ckbuilder-backup.json
```

The JSON backup contains the credential ledger and operational product data but deliberately excludes administrator password hashes and submission tracking hashes.

## Test expansion

v4 adds dedicated tests for:
- timeline creation and transition history;
- resubmission and cancellation state guards;
- tracking-token authorization;
- search and SQL-injection-shaped input handling;
- aggregate statistics and operation filtering;
- safe operational export;
- malformed password-hash iteration handling;
- Gemini BYOK request/response adaptation;
- webhook URL policy, HMAC signing, delivery success/failure, and DNS private-address blocking;
- public readiness/stats/directory behavior;
- public submission timeline/resubmit/cancel HTTP workflows;
- authenticated issuer bulk intake, search, stats, export, operations and state guards.

The original v1-v3 test suites remain in place as regression coverage.
