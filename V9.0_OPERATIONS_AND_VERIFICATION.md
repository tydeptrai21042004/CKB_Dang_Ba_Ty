# CKBuilder v9.0 — Agent Operations & Verification

v9 turns the v8 agent-service demo flow into a repeatable operator workflow. The design keeps the existing hard boundary: AI agents do not receive signing keys, cannot broadcast CKB transactions, cannot execute Fiber payments, and cannot make autonomous spending decisions.

## New production-oriented capabilities

### 1. Private persistent agent jobs
Completed Agent Service Hub jobs are stored in `DATA_DIR/agent-jobs.json` with mode `0600`. Each completed job receives a random `jobAccessToken`; the server stores only its SHA-256 hash. A job can be reopened only with its job ID + token. There is deliberately no public endpoint that lists job objectives.

The browser keeps recent job tokens in `sessionStorage` only, so closing the tab removes its convenience history without deleting the private server record.

### 2. Evidence-derived service reputation
`/api/config` exposes only aggregate execution statistics per service: job count, full-evidence fulfillment rate, tool success rate, gaps/blocked counts and latest timestamp. User objectives, output text, job tokens, RPC URLs and connector secrets are not included.

### 3. Pre-execution service agreements
`POST /api/agent-commerce/agreement` creates a deterministic agreement before model execution. It binds the service, objective hash, evidence policy, maximum reasoning/tool steps, payment mode and the fixed `autonomousSpend=false`, `signingAuthority=false`, `broadcastAuthority=false` terms. If a supplied agreement is modified or used for a different objective, `/api/agent-commerce/run` rejects it before any model call.

### 4. Independent receipt verification
`POST /api/agent-commerce/verify-receipt` recalculates the receipt hash and application-defined CKB anchor payload. When the agreement and fulfillment record are supplied, their hashes are cross-checked too.

Offline CLI:

```bash
npm run agent:receipt:verify -- ./agent-evidence-pack.json
```

### 5. Deterministic CKB transaction preflight
`POST /api/agent-commerce/transaction-preflight` validates a raw transaction without AI. It checks CKB Script structure, input/output arrays, duplicate input out-points, output/data cardinality, hexadecimal quantities, dependency/witness warnings, output capacity totals and a deterministic risk level. If `CKB_RPC_URL` is configured it may additionally call only `dry_run_transaction`.

Offline structural CLI:

```bash
npm run agent:tx:preflight -- ./transaction.json
```

The preflight layer has no signing or broadcast capability.

### 6. Agent Runtime Doctor
`GET /api/agent-commerce/doctor` reports which installed plugins are ready, require configuration, or contain invalid local configuration. It intentionally does not return RPC endpoints, local workspace paths, GitHub tokens or wallet data.

### 7. Portable evidence-pack export
The browser can export the current/reopened agent job as `ckbuilder-agent-evidence-pack/v1`: service metadata, agreement, deterministic fulfillment evaluation, cryptographic receipt, final answer and audited tool trace. BYOK API keys and server connector secrets are not part of the result object and therefore are not exported.
