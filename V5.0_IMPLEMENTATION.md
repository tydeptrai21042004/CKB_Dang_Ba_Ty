# CKBuilder Passport v5.0 implementation

## Goal

v5 adds real browser-document and evidence-file workflows without allowing HTML, uploaded files, or AI to cross the trust boundary. Cryptographic signature verification, SHA-256 document matching, issuer trust, CKB Cell state, revocation, and conflict detection remain authoritative.

## Document pipeline

`src/lib/document-service.js` provides bounded canonical-base64 decoding, MIME/extension consistency checks, binary signature sniffing for PDF/PNG/JPEG/WebP, UTF-8 validation, HTML visible-text extraction, HTML sanitization, deterministic SHA-256 inspection, and a supported-document catalog.

Supported formats are HTML, TXT, Markdown, JSON, PDF, PNG, JPEG, and WebP. SVG and other active formats are rejected.

HTML previews remove executable/embedded blocks, forms, links, images, styles, metadata and every HTML attribute. The browser additionally renders previews in a sandboxed iframe.

## Evidence attachments

Applicants may upload up to 10 files, at most 5 MB each. Files are stored under `DATA_DIR/product-attachments` with random IDs, private directory/file modes, and database metadata containing name, MIME type, byte length, and SHA-256.

Tracking-token authorization is required to add/list/remove attachments. Files can be changed only while the submission is `SUBMITTED` or `CHANGES_REQUESTED`.

Issuer endpoints require authenticated admin sessions. Raw HTML is always returned as `application/octet-stream` with `Content-Disposition: attachment`; HTML/text previews are sanitized. Each read recomputes byte length and SHA-256 and fails with `ATTACHMENT_INTEGRITY_FAILED` on drift.

## HTML credential output

`src/lib/credential-html.js` creates a printable script-free HTML credential. User-controlled fields are HTML-escaped and the endpoint uses a restrictive CSP. The page includes a current verification URL rather than claiming the static HTML itself proves live chain state.

## AI

`analyzeCredentialDocument()` supports text extraction from HTML/TXT/Markdown/JSON and vision input for PNG/JPEG/WebP. Extracted document text is bounded and surrounded by an explicit untrusted-data boundary in the prompt. PDF remains deterministic-only to avoid provider-specific file APIs.

AI still has no signing key, CKB transaction authority, reviewer approval authority, trusted-issuer mutation, or ability to override deterministic verification.

## Storage operations

- `npm run attachments:audit` checks missing, tampered, and orphaned evidence files.
- `npm run backup:export` exports metadata + ledger only.
- `npm run backup:export:full` first requires a clean attachment audit, then creates a private backup directory containing the manifest and raw attachments.

## Main v5 endpoints

Public:

- `POST /api/document/inspect`
- `POST /api/ai/document`
- `GET /api/certificate/:credentialId/html`
- `POST /api/submissions/:id/attachments`
- `GET /api/submissions/:id/attachments?token=...`
- `DELETE /api/submissions/:id/attachments/:attachmentId`

Issuer/admin:

- `GET /api/admin/submissions/:id/attachments`
- `GET /api/admin/attachments/:id/preview`
- `GET /api/admin/attachments/:id/download`
- `GET /api/admin/attachments/audit`
