# CKBuilder Passport v6.0 — Tool-Using CKB Agents and Community Plugins

Version 6 upgrades the previous prompt-routed AI workbench into a bounded, auditable tool-using agent runtime.

## What changed

### 1. Multi-step agent runtime

`POST /api/ai/agent` can now run up to 1–6 model/tool steps. The model may call tools, receive their bounded results as untrusted data, and then synthesize a final answer. The response includes:

- selected specialist agent;
- provider/model;
- enabled plugin metadata;
- number of agent steps;
- `toolTrace` with plugin, tool, risk, status, and duration;
- `approvalRequired` when an unverified MCP tool is not explicitly read-only.

The runtime still never treats AI output as credential validity, issuance approval, or authoritative chain state.

### 2. Native provider tool schemas

Tool definitions are translated to the provider's native request shape:

- OpenAI-compatible function tools;
- Anthropic `tools` / `tool_use`;
- Gemini function declarations / function calls.

This preserves the existing BYOK providers while giving the agent a real action loop rather than relying only on prompt text.

### 3. Built-in CKB plugins

| Plugin | Default | Capability |
|---|---:|---|
| `ckb-docs` | On | Searches the official `docs.nervos.org/llms.txt` resource |
| `ckb-community` | On | Reads recent public Nervos Talk topics and returns curated developer/community resources |
| `ckb-rpc` | Off | Read-only CKB JSON-RPC using the deployment-configured RPC URL |
| `ckb-ai-mcp` | Off | Discovers tools from the community CKB AI MCP endpoint |

The CKB RPC plugin exposes only a fixed read allowlist. No `send_transaction`, signer, wallet, or private-key method is present.

### 4. MCP support

`src/lib/mcp-client.js` supports:

- current stateless Streamable HTTP MCP requests;
- JSON and request-scoped SSE responses;
- `tools/list` discovery;
- `tools/call` execution;
- fallback to the legacy initialize/session flow for older MCP servers;
- HTTPS-only remote endpoints (HTTP allowed only for localhost).

### 5. Community plugin manifests

Community MCP integrations can be added as data-only files:

```text
plugins/community/*.json
```

Example:

```json
{
  "schemaVersion": 1,
  "id": "my-ckb-plugin",
  "name": "My CKB Community MCP",
  "description": "Read project data for builders.",
  "source": "My CKB project",
  "transport": "mcp",
  "endpoint": "https://example.org/mcp"
}
```

Community manifests are disabled by default in the UI. CKBuilder does not dynamically import or execute JavaScript from the community plugin directory.

### 6. Human approval and hard safety boundary

MCP tools explicitly annotated read-only can run when their plugin is enabled. Unannotated/external tools stop and return an approval request. The browser shows the plugin, tool name, and arguments before the user can approve one execution.

Regardless of approval, tool names that resemble signing, transaction broadcast, private-key, mnemonic, or seed operations are hard-blocked. AI provider API keys are never forwarded to plugins.

### 7. Agent Workbench UI

The public workbench now displays:

- specialist selector;
- enabled plugin checkboxes with trust/permissions;
- maximum tool/reasoning steps;
- explicit no-signing/no-broadcast boundary;
- final answer;
- per-tool audit trace;
- confirmation prompt for unannotated MCP operations.

## Tests

Run the v6-focused suite:

```bash
npm run test:v6
```

Run all AI/provider/agent tests:

```bash
npm run test:ai
```

Run the complete repository suite:

```bash
npm test
```

The v6 tests cover MCP current and legacy transports, SSE, plugin discovery, community manifests, RPC read-only restrictions, provider-native function schemas, tool-call parsing, multi-step execution, prompt-injection isolation through tool results, recovery from failed tools, step limits, user approval, and hard blocking of signing/broadcast tools.

## Community contributor workflow

A CKB community project does not need to modify the agent runtime to integrate. Add a data-only manifest under `plugins/community/`, validate it with `npm run plugins:check`, and exercise the MCP compatibility/security suite with `npm run test:v6`. The JSON Schema is shipped at `plugins/plugin-manifest.schema.json` for editor/CI validation.
